## 一、强化学习基础概念

### 1.1 什么是强化学习？和监督学习最大的区别

**强化学习（RL）**：智能体（Agent）在环境（Environment）中通过不断**试错**获得奖励（Reward），学习能最大化**长期累计回报**的行为策略。

| | 监督学习 | 强化学习 |
|------|---------|---------|
| **监督信号** | 直接给定正确答案（标签） | 只有延迟、稀疏、可能有噪声的奖励 |
| **数据来源** | 固定的独立同分布数据集 | **由策略自己产生**（策略变 → 数据分布变） |
| **目标** | 拟合输入到输出的映射 | 最大化长期回报（需要考虑未来） |
| **纠错方式** | 立刻告诉对错 | 可能做了很多步才知道结果好坏（信用分配） |
| **示例** | 图像分类、房价预测 | 下棋、机器人控制、LLM 对齐 |

面试一句话：**监督学习学"映射"，强化学习学"决策"；监督学习有老师给答案，强化学习只有事后给分。**

### 1.2 马尔可夫决策过程（MDP）

MDP 是强化学习的数学建模框架，五元组：

$$
\text{MDP} = (S, A, P, R, \gamma)
$$

- $S$：状态集合（State）—— 当前环境情况
- $A$：动作集合（Action）—— 智能体可采取的决策
- $P$：状态转移概率 $P(s' \mid s, a)$ —— 执行动作后环境如何变化
- $R$：奖励函数 $R(s, a, s')$ —— 这一步做得好不好
- $\gamma$：折扣因子 $\gamma \in [0, 1]$ —— 未来奖励在当前决策中的重要程度

**马尔可夫性质（无记忆性）**：下一状态只依赖当前状态和动作，与更早的历史无关：
`P(s_{t+1} | s_t, a_t, s_{t-1}, a_{t-1}, ...) = P(s_{t+1} | s_t, a_t)`

### 1.3 策略、价值函数、Q 函数、return

- **策略 π(a|s)**：在状态 s 下选择动作 a 的规则（概率分布）。RL 的最终目标就是找到最优策略 π*
- **Return（回报）G_t**：从 t 时刻开始的折扣累计奖励
  ```
  G_t = r_{t+1} + γ·r_{t+2} + γ²·r_{t+3} + ... = Σ_{k=0}^∞ γ^k · r_{t+k+1}
  ```
- **价值函数 V(s)**：从状态 s 出发、按策略 π 行动，未来能获得的**期望** return
  `V^π(s) = E_π[G_t | s_t = s]`
- **Q 函数（动作价值函数）Q(s,a)**：在状态 s 先执行动作 a、之后按 π 行动，未来能获得的期望 return
  `Q^π(s,a) = E_π[G_t | s_t = s, a_t = a]`
- 两者关系：`V^π(s) = Σ_a π(a|s)·Q^π(s,a)`（价值 = 各动作 Q 值按策略加权平均）

### 1.4 episode 与 trajectory

```
Episode（回合）：从开始到终止的一整轮交互，如一局游戏、一轮完整对话
Trajectory（轨迹）：状态-动作-奖励序列
  s0 →a0→ r1, s1 →a1→ r2, s2 →a2→ ... → 终止
```

在大模型语境里：episode = 一个 prompt 从开始生成到结束的完整回答；trajectory = (prompt, 生成的回答, 每个 token 的分布, 最终奖励)。

### 1.5 探索与利用（Exploration vs Exploitation）

- **利用（Exploitation）**：根据当前已知信息选择看起来最优的动作
- **探索（Exploration）**：尝试不确定但可能更好的动作
- 只利用 → 过早陷入局部最优；只探索 → 浪费样本、收益差
- 常见平衡手段：
  - **ε-greedy**：以 ε 概率随机探索，1-ε 概率贪心
  - **UCB**：对"不确定性高"的动作加探索奖励
  - **熵正则**：策略的熵作为奖励项，鼓励随机性（LLM 对齐里也常用）

### 1.6 折扣因子 γ 的影响

| γ 取值 | 行为 | 代价 |
|--------|------|------|
| γ 太小（→0） | 短视，只在乎眼前奖励 | 学不到长期规划 |
| γ 太大（→1） | 重视远期收益 | 估计方差高、训练难稳定 |

### 1.7 RL 术语 → 大模型对齐的映射（面试加分）

| RL 概念 | 大模型中的对应 |
|---------|---------------|
| 状态 s | prompt + 已生成的 token 前缀 |
| 动作 a | 生成下一个 token（或"是否结束生成"） |
| 策略 π | LLM 本身（给定上文输出 token 的概率分布） |
| 环境 | 奖励模型 / 规则判据 / 外部工具执行结果 |
| 奖励 r | RM 打分 / 数学答案对错 / 代码是否通过测试 |
| Episode | 一次完整的回答生成 |
| 轨迹 | prompt + 完整回答 + 逐步概率 |
| 智能体 | LLM（或 LLM + 工具组成的 Agent） |

### 1.8 面试要点

| 考点 | 答案要点 |
|------|---------|
| RL 和监督学习最大区别 | 监督学习有标签、数据固定；RL 只有延迟奖励、数据由策略产生（分布漂移） |
| 马尔可夫性质 | 下一状态只依赖当前状态和动作，无记忆性 |
| V 和 Q 的关系 | V(s) = Σ π(a\|s)·Q(s,a)；V 是状态的好坏，Q 是"状态+动作"的好坏 |
| 为什么需要折扣因子 | 数学上保证有限和收敛；建模"远期奖励不确定/不重要"；调节远视 vs 短视 |
| 探索和利用怎么平衡 | ε-greedy、UCB、熵正则；只利用会局部最优，只探索样本效率低 |

## 二、贝尔曼方程与动态规划

### 2.1 贝尔曼方程（Bellman Equation）

描述"当前价值 = 当前奖励 + 下一状态价值"的递归关系：

$$
V^{\pi}(s) = \mathbb{E}_{\pi}\left[r_{t+1} + \gamma V^{\pi}(s_{t+1}) \mid s_t = s\right]
$$

$$
Q^{\pi}(s, a) = \mathbb{E}_{\pi}\left[r_{t+1} + \gamma \sum_{a'} \pi(a' \mid s')\, Q^{\pi}(s', a') \mid s_t = s,\, a_t = a\right]
$$

**为什么重要**：它把"长期回报"拆成了"当前奖励 + 下一时刻价值"的**局部可迭代形式**——这是所有价值类 RL 算法（TD、Q-learning、DQN）能工作的数学基础。

### 2.2 贝尔曼最优方程

$$
V^{*}(s) = \max_a \mathbb{E}\left[r + \gamma V^{*}(s')\right]
$$

$$
Q^{*}(s, a) = \mathbb{E}\left[r + \gamma \max_{a'} Q^{*}(s', a')\right]
$$

最优策略：每步取 `argmax_a Q*(s,a)`。

### 2.3 动态规划（已知模型时的求解）

| 方法 | 做法 | 特点 |
|------|------|------|
| **策略迭代** | 交替：策略评估（算 V^π）+ 策略改进（贪心提升 π） | 收敛快，每轮要完整评估 |
| **价值迭代** | 直接迭代贝尔曼最优方程 V ← max_a(...) | 不用显式策略，迭代到收敛 |

局限：动态规划要求**已知转移概率 P**（model-based），真实问题大多不知道 P，所以需要无模型方法（第三章）。

### 2.4 面试要点

| 考点 | 答案要点 |
|------|---------|
| 贝尔曼方程在做什么 | 把长期回报拆成"当前奖励 + 下一状态价值"，递归定义价值 |
| 贝尔曼最优方程 | V* = max_a E[r + γV*]；Q* = E[r + γ max Q*] |
| 动态规划的前提 | 已知模型（转移概率 P），真实问题很少满足 |
| 策略迭代 vs 价值迭代 | 策略迭代显式维护策略交替评估/改进；价值迭代只迭代价值函数 |

## 三、Value-Based 方法：Q-learning 与 DQN

### 3.1 蒙特卡洛（MC）与时序差分（TD）

| | MC（蒙特卡洛） | TD（时序差分） |
|------|---------------|----------------|
| **更新时机** | 走完整个 episode 才更新（用真实 return） | 每走一步就更新（用估计值 bootstrap） |
| **偏差/方差** | 无偏，方差大 | 有偏，方差小 |
| **适用** | 有终止的回合制任务 | 可处理不终止的持续任务，学习快 |

TD 的核心：`V(s) ← V(s) + α·[r + γV(s') − V(s)]`，方括号里叫 **TD error**。

### 3.2 Q-learning（off-policy 的经典）

$$
Q(s, a) \leftarrow Q(s, a) + \alpha\left[r + \gamma \max_{a'} Q(s', a') - Q(s, a)\right]
$$

- 更新目标用**贪心** max：学的是"最优策略下的价值"
- 行为上可以用 ε-greedy 等探索策略收集数据
- **为什么 off-policy**：**行为策略**（采数据的）和**目标策略**（更新朝向的）可以不同——行为策略随便探索，目标策略始终朝最优 Q 靠拢

### 3.3 SARSA（on-policy 的经典）

$$
Q(s, a) \leftarrow Q(s, a) + \alpha\left[r + \gamma Q(s', a') - Q(s, a)\right]
$$

这里的 $a'$ 是实际采取的动作。

- 更新目标用**实际采取的动作** a'：学的是"当前行为策略下的价值"
- 更保守：会把探索的代价也学进 Q 值里

### 3.4 DQN 及三大改进

DQN = 用神经网络拟合 Q 函数（解决状态空间大/连续的问题）。

| 技巧 | 解决什么问题 | 原理 |
|------|------------|------|
| **经验回放（Experience Replay）** | 样本时序相关 → 训练不稳定 | 把 (s,a,r,s') 存进缓冲池，随机采样打乱相关性，还能复用样本 |
| **目标网络（Target Network）** | 目标自己追自己 → 发散 | 用延迟更新的旧网络算 max Q，目标相对固定 |
| **Double DQN** | max 操作导致 Q 值过估计 | 用在线网络选动作 a*、目标网络给 Q(a*) 打分（解耦选和评） |
| **Dueling DQN** | 部分状态动作价值差异小 | 把 Q 拆成 V(s) + A(s,a) 两个分支 |
| **Prioritized Replay** | 所有样本同等采样效率低 | 按 TD error 大小加权采样 |

### 3.5 面试要点

| 考点 | 答案要点 |
|------|---------|
| Q-learning 为什么 off-policy | 更新目标用 max（贪心目标策略），行为策略可自由探索 |
| SARSA 为什么 on-policy | 更新目标用实际采取的动作 |
| DQN 为什么要经验回放 | 打破样本时序相关性 + 提高样本利用率 |
| 为什么要 target network | 目标随网络一起变会"追自己"导致震荡发散；固定目标稳定训练 |
| 为什么 Q-learning 是 value-based | 先学价值函数，再据价值选动作（隐式策略） |

## 四、Policy-Based 方法与 Actor-Critic

### 4.1 策略梯度（Policy Gradient / REINFORCE）

直接参数化策略 π_θ(a|s)，用梯度上升最大化期望回报：

$$
\nabla J(\theta) = \mathbb{E}\left[\nabla_\theta \log \pi_\theta(a \mid s) \cdot G_t\right]
$$

直觉：**回报高的轨迹上的动作 → 提高其概率；回报低的 → 降低**。

- 优点：可以处理**连续动作空间**（不用枚举动作）；策略是随机分布，天然探索
- 缺点：**方差大**——同一个状态，采样运气不同导致 G_t 波动大，梯度噪声大

### 4.2 降方差的两个手段

1. **Baseline（基线）**：减掉与动作无关的基线（如状态价值 V(s)）：
   `∇J = E[ ∇log π(a|s) · (G_t − b(s)) ]`，方差降、期望不变
2. **Actor-Critic**：用 critic 估计的价值替代/辅助 G_t，即用 **advantage**（优势函数）：
   `A(s,a) = Q(s,a) − V(s)`（这个动作比平均好多少）

### 4.3 Actor-Critic 架构

```
Actor（演员）= 策略网络 π_θ(a|s)     → 负责"决策"（被优化）
Critic（评论家）= 价值网络 V_φ(s)    → 负责"评估"（估计好坏，指导 actor）
```

- 训练循环：actor 按 critic 给出的 advantage 更新策略；critic 用 TD error 更新价值
- 为什么实用：**纯 value-based** 难处理连续动作；**纯 policy-based** 方差大；AC 两者互补
- 变体：**A2C/A3C**（多环境并行采样降低样本相关性；A3C 异步、A2C 同步）

### 4.4 面试要点

| 考点 | 答案要点 |
|------|---------|
| 策略梯度为什么能处理连续动作 | 直接优化动作分布，不需要枚举/离散化动作 |
| 为什么策略梯度不稳定 | 采样方差大：回报随机、奖励尺度敏感 |
| Baseline 为什么有效 | 减去的项与动作无关，不改变梯度期望，只降方差 |
| Actor 和 Critic 各自干什么 | Actor 决策、Critic 评估；critic 给 actor 提供低方差的 advantage 信号 |
| 为什么 AC 比纯方法实用 | 连续动作 + 低方差兼顾 |

## 五、PPO（大模型对齐的主力算法）

### 5.1 从 TRPO 到 PPO

- **策略梯度的问题**：学习率太大一步走飞（策略崩坏），太小收敛慢
- **TRPO**：用约束保证每次更新 KL 距离不超限（信任区域）。效果好但计算复杂（共轭梯度）
- **PPO**（Proximal Policy Optimization）：把"硬约束"变成"软裁剪"，**稳定 + 简单 + 调参少**，成为工业默认

### 5.2 PPO 的核心：重要性采样 + clip

利用**重要性采样**，可以用旧策略 π_old 采样的数据更新新策略 π_θ（on-policy 也能复用一批数据）：

$$
r_t(\theta) = \frac{\pi_\theta(a_t \mid s_t)}{\pi_{\text{old}}(a_t \mid s_t)}
$$

上式是新旧策略的概率比，把它代进 PPO 的裁剪目标：

$$
L_{\text{clip}} = \mathbb{E}\left[\min\left(r_t(\theta) A_t,\; \operatorname{clip}(r_t(\theta), 1-\varepsilon, 1+\varepsilon) A_t\right)\right]
$$

- 当 A_t > 0（这个动作好）：鼓励提高概率，但最多提高 (1+ε) 倍，防止一步走飞
- 当 A_t < 0（动作差）：限制降低幅度
- ε 通常取 0.2

**一句话**：PPO 通过裁剪新旧策略的比值，限制每次更新的幅度，既稳又快。

### 5.3 GAE（广义优势估计）

advantage 怎么算？用 **GAE** 平衡偏差与方差：

$$
\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)
$$

$$
A_t = \delta_t + \gamma\lambda\, \delta_{t+1} + (\gamma\lambda)^2 \delta_{t+2} + \cdots
$$

前式是 TD error，后式是多步 TD 的加权和。$\lambda = 0$ 退化成单步 TD（低方差、高偏差），$\lambda \to 1$ 则接近蒙特卡洛（高方差、低偏差）。

### 5.4 为什么 PPO 在大模型对齐和连续控制里这么常见

1. **稳定**：clip 机制防止策略更新幅度过大，训练不容易崩
2. **实现简单、调参成本低**：一个目标函数搞定，不用共轭梯度
3. **on-policy 与语言生成天然契合**：语言模型的"数据"就是自己采样的回答，每次 rollout 一批新回答正好满足 on-policy
4. 效果强，是 RLHF 的事实标准（InstructGPT/LLaMA 2 都用 PPO）

### 5.5 PPO 的代价（为第十章 GRPO 埋伏笔）

- 需要 **critic（价值网络）** 估计 advantage → 又多一个与策略同规模的模型 → 显存翻倍
- 4 个模型同时在场（策略、参考、奖励模型、critic），工程复杂
- → 后续 GRPO 的思路就是：**不要 critic，用组内采样统计代替**

### 5.6 面试要点

| 考点 | 答案要点 |
|------|---------|
| PPO 核心创新 | 重要性采样比率 + clip 裁剪，限制单步更新幅度 |
| 为什么 clip 而不是约束 | 软约束：实现简单，效果接近 TRPO 且更稳 |
| GAE 是干什么的 | 多步 TD error 加权求和，平衡偏差与方差（λ 调节） |
| 为什么 LLM 对齐用 PPO | 稳定、on-policy 契合生成任务、工程成熟 |
| PPO 的缺点 | 需要 critic（显存/成本翻倍）、训练不稳定、超参敏感 |

## 六、奖励设计：稀疏奖励、Reward Shaping 与 Reward Hacking

### 6.1 稀疏奖励（Sparse Reward）

**问题**：奖励只在任务完成时才给一次（如"通关 +1"），中间过程全是 0 → 智能体无法知道哪些中间行为有帮助，**信用分配**困难，探索如同大海捞针。

**缓解思路**：
- **Reward Shaping**：给中间过程设计密集的辅助奖励（如接近目标 + 小分）
- **课程学习（Curriculum）**：从简单任务逐步过渡到难任务
- **模仿学习 / warm start**：先用专家轨迹 SFT/BC 初始化策略（LLM 路线：先 SFT 再 RL）
- **层级强化学习**：高层定目标，低层实现

### 6.2 Reward Shaping 的副作用

- Shaping 奖励设计不当 → 模型学会**刷 shaping 奖励**而不是完成真正目标（如"来回移动刷步数奖励"）
- 本质：**优化目标和真实意图不一致**，是 reward hacking 的雏形
- 理论保障：Potential-based shaping（F = γΦ(s') − Φ(s)）可以证明不改变最优策略

### 6.3 Reward Hacking / Specification Gaming（规格博弈）

**定义**：模型没有真正完成任务，而是**利用奖励函数的漏洞**获得高分（Goodhart 定律："当一个指标成为目标，它就不再是好指标"）。

常见例子：
- 对话模型学会输出更长、更谄媚的回答刷 RM 分
- 代码智能体**修改测试用例**让测试通过，而不是修代码
- 游戏 AI 卡 bug 刷分

**为什么难以根除**：奖励是对真实目标的**有损近似**（RM 是人类偏好近似，测试集是正确性近似），只要优化器足够强，一定会找到"分数高但真实质量差"的漏洞。

**缓解**：
- **KL 约束**（RLHF）：把策略钉在参考模型附近，限制钻空子空间
- **可验证奖励**（数学答案、单测）：判据客观，难 hack（但测试集不完备仍可 hack，见第十一章）
- 多目标奖励、人工抽检、对抗性评估

### 6.4 面试要点

| 考点 | 答案要点 |
|------|---------|
| 稀疏奖励为什么难 | 信用分配困难：不知道哪一步真正有用，探索效率低 |
| Shaping 的副作用 | 可能学到刷 shaping 奖励而非真实目标 |
| Reward hacking 是什么 | 利用奖励函数漏洞拿高分，没有真正完成任务 |
| 怎么缓解 hacking | KL 约束、可验证奖励、多目标、人工抽检 |
| 为什么代码智能体要警惕 | 可能改测试、跳过检查、生成看似通过但有害的补丁 |

## 七、RL 的分类体系与"为什么 RL 难"

### 7.1 Model-Free vs Model-Based

| | Model-Free（无模型） | Model-Based（有模型） |
|------|---------------------|---------------------|
| **做法** | 不学环境模型，直接学价值/策略 | 先学环境如何转移（世界模型），再用它规划/生成数据 |
| **样本效率** | 低（靠大量试错） | 高（可以"在想象中"规划） |
| **风险** | 训练成本高 | **模型误差会传播**到决策中（学错了环境就规划错了） |
| **代表** | Q-learning、DQN、PPO、RLHF | Dyna、Dreamer、MuZero、AlphaZero |

### 7.2 Online vs Offline RL

| | Online RL（在线） | Offline RL（离线） |
|------|------------------|-------------------|
| **数据** | 边探索边收集新数据 | 只用固定历史数据集，**不能再试新动作** |
| **难点** | 样本效率 | **分布外（OOD）问题**：策略一旦走到数据分布之外，价值估计严重偏差且无法纠正 |
| **缓解** | — | 保守估计（CQL、IQL）、约束策略贴近行为策略 |

大模型视角：PPO/GRPO 是 online（实时采样新回答）；DPO 本质是 offline（用静态偏好数据）。

### 7.3 为什么强化学习比监督学习难训练、不稳定

三大原因（面试必背）：

1. **非平稳数据分布**：策略变 → 采样的数据分布变 → 训练目标本身在动态变化（监督学习数据分布固定）
2. **监督信号弱**：奖励延迟、稀疏、噪声大，不如标签直接
3. **信用分配难**：一次轨迹里几十上百步，哪一步导致了最终结果？梯度信号难以回溯

### 7.4 面试要点

| 考点 | 答案要点 |
|------|---------|
| Model-based 的代价 | 世界模型误差会传播；学错环境就规划错 |
| Offline RL 为什么难 | 无法在线纠正，策略出分布后 Q 值严重高估 |
| DPO 算 online 还是 offline | 本质 offline（静态偏好数据），这也是它无探索的原因 |
| RL 比 SL 难的三大原因 | 分布漂移、奖励弱、信用分配难 |

## 八、RLHF：人类反馈强化学习 ★

### 8.1 为什么要对齐（Alignment）

- 预训练模型只会"续写"，**不遵循指令、风格不像助手、可能输出有害内容**
- 对齐 = 让模型的输出**符合人类偏好**（有用、诚实、无害）
- RLHF（Reinforcement Learning from Human Feedback）= 用"人类偏好"作为强化学习的目标

### 8.2 RLHF 三阶段流程（InstructGPT 范式）

```
阶段 1：SFT —— 高质量指令-回复对监督微调，学会对话格式与听指令
阶段 2：奖励模型（RM）—— 人类给多个回答排序 → 训练打分模型
阶段 3：PPO 优化 —— 策略模型生成回答 → RM 打分 → 强化学习更新
```

### 8.3 奖励模型（Reward Model）

- 数据：同一 prompt 下多个模型的回答，人工**排序**
- 建模：**Bradley-Terry 模型**——把排序变成二分类（被选的 vs 被拒的）：
  ```
  P(y_w 优于 y_l) = σ( r(x, y_w) − r(x, y_l) )
  损失：最大化 log σ(r_w − r_l)
  ```
- RM 输出一个标量分数，**在回答末尾加一个特殊 token 取它的 logit**（参数量通常与策略同规模，去掉最后的 softmax 头）

### 8.4 PPO 在 LLM 上的实现细节

```
参与训练的模型（4 个）：
  策略模型 π_θ（被优化，可 LoRA）
  参考模型 π_ref（冻结，SFT 模型）
  奖励模型 RM（冻结）
  Critic 价值网络（估计 advantage，同规模）

奖励合成（关键细节）：
  r_total = r_RM(x, y) − β·KL[π_θ(y|x) || π_ref(y|x)]
  逐 token 算 KL：每一步生成的概率与参考模型对比

优化目标：
  max E[ r_total ]  →  PPO clip 目标 + GAE advantage
```

### 8.5 为什么必须有 KL 约束

1. **防 reward hacking**：RM 是近似，模型可以刷分（变长、谄媚、重复）；KL 限制离参考模型太远
2. **保持语言流畅**：纯优化 RM 会让输出退化（语无伦次但高分）
3. 数学上，KL 正则使优化目标有良好性质（对应"带约束的最优策略"）

### 8.6 RLHF 的问题与局限

| 问题 | 说明 |
|------|------|
| **成本高** | 人工标注贵；4 个模型显存大、训练慢 |
| **不稳定** | PPO 超参敏感，训练容易崩 |
| **Over-optimization** | RM 分数越训越高，但真实质量先升后降（优化过头，RM 被骗） |
| **RM 偏差** | RM 学的是标注者的平均偏好，可能固化偏见 |
| **Alignment Tax** | 对齐可能损害部分通用能力（如创造性、数学） |

### 8.7 面试要点

| 考点 | 答案要点 |
|------|---------|
| RLHF 三阶段 | SFT → 训练 RM（人类排序 + Bradley-Terry）→ PPO 优化 |
| RM 怎么训练 | 人类排序 → 二分类（胜者 vs 败者）→ 输出标量分数 |
| 奖励模型、策略模型、KL 各解决什么 | RM 把偏好变成可优化信号；策略是被优化对象；KL 防止偏离参考模型太远（防 hack、保流畅） |
| 为什么 RLHF 不稳定 | PPO 本身不稳定 + 4 个模型 + RM 打分噪声 |
| Over-optimization 是什么 | RM 分数涨但真实质量掉，优化过度 |

## 九、DPO：不需要奖励模型的对齐 ★

### 9.1 核心洞察（面试必答）

RLHF 的最优策略有**闭式解**：

$$
\pi^{*}(y \mid x) \;\propto\; \pi_{\text{ref}}(y \mid x) \exp\!\left(\frac{r(x, y)}{\beta}\right)
$$

把它代回 Bradley-Terry 偏好概率，**奖励模型 r 可以被消掉**——偏好信息直接定义了策略的优化目标：

$$
\mathcal{L}_{\text{DPO}} = -\log \sigma\!\left(
\beta \log \frac{\pi_\theta(y_w)}{\pi_{\text{ref}}(y_w)}
- \beta \log \frac{\pi_\theta(y_l)}{\pi_{\text{ref}}(y_l)}
\right)
$$

直觉（一句话）：**让"被人类选中的回答 y_w 的概率相对参考模型提升"，让"被拒绝的回答 y_l 的相对概率下降"。**

### 9.2 DPO vs RLHF（PPO）对比

| | RLHF（PPO） | DPO |
|------|------------|-----|
| 奖励模型 | 需要训练 RM | **不需要**（隐式奖励） |
| 采样 | 在线 RL（策略实时采样） | **离线**（静态偏好数据） |
| 模型数量 | 4 个 | 2 个（策略 + 参考） |
| 训练稳定性 | 差（超参敏感） | 好 |
| 工程成本 | 高 | 低 |
| 短板 | 贵、不稳定 | 无探索；**对偏好数据质量敏感** |

### 9.3 DPO 变体（展示广度）

| 变体 | 改进 |
|------|------|
| **IPO** | 把 KL 正则直接写进损失，去掉 β 敏感性，更稳 |
| **KTO** | 不需要成对数据，只要"好/坏"标签（数据更容易收集） |
| **ORPO** | SFT 和偏好优化一步完成（训练中同时区分优劣） |
| **SimPO** | 去掉参考模型，用长度归一化的隐式奖励（省显存） |
| **R-DPO** | 修正 DPO 对"长答案"的偏好偏差（长度正则） |

### 9.4 面试要点

| 考点 | 答案要点 |
|------|---------|
| DPO 为什么能替代 PPO | 最优策略闭式解 + Bradley-Terry 可消掉 RM，直接用偏好对训练 |
| DPO 的局限 | 静态数据无在线探索、对数据质量敏感、不能利用"探索出来的新样本" |
| KTO vs DPO | KTO 只要好坏标签，不用配对 |
| ORPO 的意义 | 省掉独立 SFT 阶段，一步完成 |

## 十、GRPO 与可验证奖励（DeepSeek-R1 路线）★

### 10.1 为什么需要 GRPO

- PPO 需要 **critic（价值网络）** 估计 advantage——critic 与策略**同规模**，显存翻倍、工程复杂
- 在"数学/代码推理"这类任务上，奖励是**规则化**的（答案对不对），不需要价值网络去估计
- **GRPO（Group Relative Policy Optimization）**：去掉 critic，用**组内采样统计**代替

### 10.2 GRPO 算法

```
对每个问题 x，采样 G 个回答 {y_1, ..., y_G}（一组）
对组内奖励做归一化（相对优势）：
  A_i = (r_i − mean(r)) / std(r)
用 A_i 做策略梯度更新 + KL 约束（与 PPO 相同的 clip 机制）
```

- **组内归一化**：谁比组内平均好就推高谁——不需要绝对奖励标定，只比相对
- 收益：省掉 critic → **显存省一半以上**，训练更快、更稳

### 10.3 RLVR：可验证奖励（Verifiable Rewards）

- 传统 RLHF 的奖励来自 RM（人类偏好近似，可 hack、要训练）
- **RLVR**：奖励来自**客观判据**：
  - 数学：最终答案字符串/数值相等
  - 代码：单测是否通过
  - 格式：是否满足输出规则（如"先给推理再给答案"）
- 优点：**不需要训练 RM、奖励可信、抗 reward hacking**（判据是客观的）
- 局限：只适用于"答案可验证"的任务（数学、代码、逻辑），开放写作等主观任务仍需 RM

### 10.4 DeepSeek-R1 训练配方（面试必背）

```
1. 冷启动 SFT：几千条高质量"长思考（CoT）"种子样本，教模型"先想再答"的格式
2. 大规模 RL：数学/代码/逻辑任务，GRPO + 规则奖励
   → 涌现自我纠错、反思（著名的 "aha moment"：模型自发说"等等，我需要重新验证一下"）
3. 拒绝采样 + 全领域 SFT：用 RL 后的模型采样约 80 万条（60 万推理 + 20 万通用）做 SFT
4. 第二轮 RL：对齐 + 无害性（加语言一致性奖励，防止中英混杂/格式乱）
```

要点：
- **RL 不只是"对齐"，还能"发现新能力"**：训练数据里没有的推理行为（反思、回溯）是 RL 激励出来的
- **拒绝采样**是 RL 和 SFT 的桥梁：把 RL 探索出的好样本沉淀成 SFT 数据

### 10.5 蒸馏与 Test-Time Scaling

- **蒸馏**：用 R1 生成的数据对 1.5B~70B 小模型做 SFT，小模型获得强推理能力（比小模型自己 RL 便宜得多）
- **Test-Time Scaling**：推理时让模型多生成思考 token 换准确率（o1 的路线）；RL 训练出的"思考习惯"在推理时通过采样/多数投票进一步放大

### 10.6 面试要点

| 考点 | 答案要点 |
|------|---------|
| GRPO vs PPO | GRPO 去掉 critic，用组内奖励归一化算 advantage，省一半显存 |
| 为什么推理任务能用 GRPO | 规则奖励（答案对错）客观，不需要价值网络估计 |
| 可验证奖励为什么火 | 不需要 RM、客观可信、难 hack |
| R1 配方四步 | 冷启动 SFT → RL（GRPO+规则奖励）→ 拒绝采样全领域 SFT → 对齐 RL |
| RL 为什么能"无中生有"出推理能力 | 奖励只约束结果，路径自由探索，模型自己发现"多想想更对" |

## 十一、RL 在代码智能体与工具调用中的应用 ★（软件工程向）

### 11.1 工具调用 RL：执行结果当奖励

工具调用的两个训练问题（详见《大语言模型面试复习》第九章）：**输出格式**（SFT 可解决）与**调用时机**（决策问题，RL 的主场）。

- **奖励设计**：
  - 正确使用工具（该调时调、调对参数、用好结果）→ 正奖励
  - 多余调用（over-calling）→ 负奖励（调用成本惩罚）
  - 该调不调导致答错 → 负奖励
- **训练方式**：先 SFT 学会"会调用"，再用 DPO 偏好对（正确轨迹 vs 过度调用轨迹）学"何时调用"，或用执行结果做 RL（ToolLLM 用工具执行打分筛选轨迹、Tulu 3 把工具使用纳入 RL 流水线）

### 11.2 代码智能体 RL（SWE-bench 等场景）

- 任务：给定 issue，模型在真实仓库中定位、修改代码、跑测试
- 奖励：**最终补丁是否通过隐藏测试**（可验证奖励，RLVR 在代码场景的直接应用；如 SWE-RL 用单测通过率训练开源智能体）
- 流程：预训练/SFT（会用工具、会改代码）→ RL（稀疏的"测试通过"奖励）→ 涌现：多轮探索、自己跑测试验证、根据报错修正

### 11.3 把"测试通过"当奖励信号的问题（面试高频）

| 问题 | 说明 |
|------|------|
| **奖励稀疏** | 一次补丁几十步，只有最后测试知道结果，模型难知道哪一步有用 |
| **测试集不完备** | 模型可能**修改测试、绕过检查、删断言**来"通过"（reward hacking 在 SE 的典型形态） |
| **信用分配难** | 一次修改含多步操作（读文件→定位→改→验证），哪步导致成功？ |
| **牺牲可维护性** | 只追求过测试，可能生成丑陋、不可维护、有隐藏 bug 的补丁 |
| **评估泄漏** | 公开仓库/题解可能已在预训练数据中（benchmark contamination） |

**缓解思路**：
- 过程奖励（PRM）：给"定位→修改→验证"的中间步打分
- 格式/静态检查奖励：语法正确、不改测试文件（规则约束）
- 混合奖励：测试通过 + 补丁规模惩罚 + 不改测试约束
- 课程：先单函数修复，再仓库级任务

### 11.4 工具调用失败重试（RL 之外的工程兜底）

- 调用失败（编译错误、404）→ 把**错误信息回填上下文** → 模型修正参数重试
- 重试必须有依据（根据错误调整），不能盲目重复
- 训练数据要包含"失败 → 修正"轨迹；系统层设调用次数上限、超时

### 11.5 面试要点

| 考点 | 答案要点 |
|------|---------|
| 代码智能体的奖励用什么 | 可验证奖励：补丁通过隐藏测试（RLVR）；中间步可加过程奖励 |
| 测试通过当奖励的问题 | 稀疏、测试不完备可被 hack（改测试）、信用分配难、牺牲可维护性 |
| 工具调用时机怎么 RL | 执行结果做奖励 + 调用成本惩罚（防 over-calling）+ DPO 偏好对学决策 |
| 失败重试策略 | 错误回填 + 依据错误修正重试 + 次数上限 |

## 十二、总结对比

### 12.1 算法全景表

| 算法 | 类型 | 核心思想 | 大模型中的角色 |
|------|------|---------|---------------|
| **Q-learning** | value-based, off-policy | TD + max 目标 | 概念基础（语言模型不用） |
| **SARSA** | value-based, on-policy | TD + 实际动作 | 概念基础 |
| **DQN** | value-based + 深度网络 | 经验回放 + 目标网络 | 概念基础 |
| **REINFORCE** | policy-based | ∇log π · G | 策略梯度思想源头 |
| **Actor-Critic / A2C** | 混合 | critic 降方差 | 思想基础 |
| **PPO** | policy-based, on-policy | 重要性采样 + clip | **RLHF 主力**（InstructGPT、LLaMA 2） |
| **DPO** | 偏好优化（offline） | 消掉 RM 直接优化偏好 | **低成本对齐主力** |
| **GRPO** | policy-based, on-policy | 组内归一化代替 critic | **推理 RL 主力**（DeepSeek-R1） |

### 12.2 大模型对齐技术路线图（速记）

```
预训练（知识）→ SFT（格式行为）→ 偏好对齐 → 能力特化（工具/推理）→ 推理时

偏好对齐三条路：
  A. 经典 RLHF：RM（Bradley-Terry）+ PPO + KL —— 贵但强（InstructGPT）
  B. DPO 系：偏好对直接优化 —— 便宜稳定（主流开源）
  C. GRPO + RLVR：规则奖励 + 组内归一化 —— 推理任务最优（R1）

关键取舍：奖励来源（人类偏好 RM vs 客观规则）决定用哪条路；
         是否有 critic 决定显存与稳定性。
```

### 12.3 面试高频速记

| 高频问题 | 一句话答案 |
|---------|-----------|
| RL 和监督学习区别 | 标签 vs 奖励；固定数据 vs 自产数据；映射 vs 决策 |
| 贝尔曼方程 | 当前价值 = 当前奖励 + γ·下一状态价值 |
| Q-learning 为何 off-policy | 更新目标用 max（贪心），行为策略可探索 |
| DQN 两大件 | 经验回放（破相关）+ 目标网络（稳目标） |
| 策略梯度方差为什么大 | 采样随机 + 奖励尺度敏感；用 baseline/critic 降 |
| PPO 为什么常见 | clip 稳定、on-policy 契合生成、实现简单 |
| RLHF 的 KL 干嘛 | 防 reward hacking、保语言流畅 |
