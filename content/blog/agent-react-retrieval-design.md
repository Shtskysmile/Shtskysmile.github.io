# 谁负责补召回：把单轮检索改造为 ReAct 的取舍

> 第四道 Agent 练习题：一个基于本地资料的问答助手。改造它需要先回答一个设计问题——召回不足要由模型换词来补，还是由检索本身来补。这道题的答案决定了改造的重心落在哪里。

---

## 一、题目

某笔试练习题给出一个资料检索助手。`docs/` 下五篇短文（市场概览、支付、物流、政策合规、竞争格局），`tools.py` 提供两个工具：`search(query)` 按字符重叠度检索、`read(doc_id)` 读全文。原始 `main.py` 的流程为：用用户原话检索一次，取排名第一的文档，只把这一篇交给大模型生成回答。

README 描述的失效现象有三条，均为症状而非原因：

| 现象 | 实际考点 |
| --- | --- |
| 答案分散在多篇文档时，回答只覆盖一部分 | 检索一次的召回不足 |
| 需要先找线索再顺着深入的问题，答非所问 | 缺少多轮自主检索 |
| 回答未标注来源、无法核对；查不到时硬凑 | 出处与弃答机制 |

题面要求：让模型自主完成多轮检索，最后给出有出处的回答，并能在资料确实查不到时如实说明。

## 二、失效分析

最直接的反应是修改 `main.py`：原始版本只取了 top-1，改为取 top-k、再让模型多查几轮即可。但这是在放大器上调参。把 `search` 单独运行，观察它实际召回什么：

```
问：综合来看，进入印尼市场的主要风险有哪些？
→ 返回 05_competition, 02_payment, 03_logistics
→ 04_regulation（政策/合规/准入）与 01_market_overview 落选
```

问「综合风险」，把监管准入一篇漏掉，而它恰是海外市场风险中最应出现的一篇。即使 `main.py` 改为取 top-5，这两篇也不在候选内。缺陷在检索本身，`main.py` 取一篇只是让缺陷更明显。

### 2.1 不是未匹配，而是差一点被切掉且不可见

`search` 用 bigram 重叠度打分，以 `overlap >= 3` 硬切。将每题对每篇文档的原始 overlap 打印出来：

```
Q: 综合来看，进入印尼市场的主要风险有哪些？
   01_market_overview  overlap=2
   02_payment          overlap=4
   03_logistics        overlap=3
   04_regulation       overlap=2     ← 差 1 分，被切掉
   05_competition      overlap=6

Q: 印尼风险                 （模型很自然会想到的换词）
   01/02/03/04/05      overlap 全部 = 1   ← 全空
```

两个关键性质：

1. 阈值把 `04_regulation` 切在 2 分。它实际接近门槛，但模型看不到；
2. 模型对漏掉的内容无感知。拿到空结果时，无法区分「资料确实没有」与「检索词未命中」。

这与第三道题（带记忆的个人助理）是同一结构。那道题是调用了 `search_memory` 却查到空，这道题是调用了 `search` 却只召回一部分：匹配方式决定了模型能否真正拿到证据。

## 三、必须做的设计决策：召回责任交给谁

要让「综合风险」这类问题答全，模型必须不止查一次。由此产生一个岔路口：

> 召回不足是靠模型自主换词来补，还是靠让 `search` 本身召回更宽（降阈值、返回更多候选、上向量）？

选择前者，即让模型自己换词追问，理由是它更接近真实 Agent 行为。但这一选择带出一条隐藏依赖，必须同时满足，否则策略必然失败。

模型换词，本质仍是猜关键词，只是从 `search` 的匹配算法挪进了模型的推断过程。只要工具仍按字面 bigram 算分，「风险」猜不到「合规」就是猜不到。因此该策略成立的前提是工具提供两样东西：

1. **语义匹配**——换词才有意义。将 bigram 换成 embedding + 余弦，让「风险/合规/监管」这类字面不同、语义相近的词互相命中；
2. **可见的相关度**——换词才可判断。工具必须返回 `score`，模型才能判断一次检索够不够、要不要继续换词。

改造的重心表面在 ReAct，实质在 `search`。ReAct 是允许模型多查几次的框架；能否补上召回，取决于每次检索的质量与反馈。加上循环只是必要条件。

## 四、实现

三块改动对应上述三点。

### 4.1 切块与语义检索

五篇文档每篇 250 至 320 字。按空行段落切块（跳过 `#` 标题行），得到 19 个 chunk，每块自带出处 `doc_id + title`：

```python
encoder = SentenceTransformer("BAAI/bge-small-zh-v1.5")

VECS = encoder.encode([c["text"] for c in CHUNKS], normalize_embeddings=True)

def search(query: str) -> str:
    query_vec = encoder.encode(query, normalize_embeddings=True)
    scores = VECS @ query_vec                 # 向量已归一化 → 点积即余弦
    order = np.argsort(scores)[::-1][:TOP_K]
    ...
```

`normalize_embeddings=True` 使每个向量模长为 1，余弦相似度退化为点积，一次 `VECS @ q` 得到全部得分。

检索颗粒度选段落而非整篇：整篇 300 字送入粗排会模糊定位，段落级更准，出处也更有意义。这一换法确实修复了盲区：

```
Q: 综合来看，进入印尼市场的主要风险有哪些？
   bigram 检索 top1 = 05_competition（漏 04_regulation）
   向量检索 top1 = 04_regulation (0.602)   ← 政策合规回到第一
```

### 4.2 工具暴露出处与分数

```python
lines.append(f"{chunk['doc_id']}｜{chunk['title']}｜相关度 {scores[i]:.2f}\n{chunk['text']}")
```

每个返回片段自带到出处和相关度。这一步是减幻觉的核心落点：出处让回答可核对，但前提是工具真的吐出了出处，而非让模型自己写——让模型凭记忆标来源，是把「无出处」换成「假出处」，后者更严重。分数则是弃答机制的入口：模型要能判断依据不足，需要一个可比较的数字；仅在 prompt 中写「不要硬凑」是软约束，返回 `score` 才是硬约束。

### 4.3 ReAct 循环

结构对齐第二道题的 `react_answer`：带 `tools` 发请求，模型要么给终答、要么请求调用；执行工具，将结果作为 `role: tool` 追加，进入下一轮；步数耗尽则收回工具，要求基于已有信息降级作答。

```python
for _ in range(max_step):
    resp = client.chat.completions.create(model="deepseek-chat", messages=messages, tools=TOOLS)
    assistant_msg = resp.choices[0].message
    if not assistant_msg.tool_calls:          # 不再请求工具 = 准备作答
        return assistant_msg.content
    messages.append(assistant_msg.model_dump())
    for tc in assistant_msg.tool_calls:
        result = TOOL_FUNCS[tc.function.name](**json.loads(tc.function.arguments))
        messages.append({"role": "tool", "tool_call_id": tc.id, "content": result})
```

`assistant★` 与 `tool` 的成对约束在此再次出现：带 `tool_calls` 的 assistant 消息必须连同其 `tool` 结果成对追加，`tool_call_id` 需对应。这条链在本例尤其关键——`read(doc_id)` 依赖前一步 `search` 给出的编号，是一条依赖链，配对写错即断。

### 4.4 system prompt 只定契约，不给依据

```python
SYSTEM_PROMPT = (
    "你是研究助理，请使用 search / read 工具查阅本地资料来回答用户问题。"
    "回答时必须遵守三条规则："
    "1. 每个结论后面都要用【文档编号｜标题】标注来源，只能引用工具返回结果里"
    "实际出现过的编号与标题，不要编造。"
    "2. 一次 search 只覆盖部分资料。如果已拿到的片段不足以回答，就换个角度、"
    "换关键词再查一次，直到信息够用为止；不要只查一次就作答。"
    "3. 如果所有检索结果的相关度都很低（比如低于 0.5），说明资料里没有依据，"
    "就明确回答「资料中没有相关信息」，不要根据常识推测或编造。"
)
```

规则 1 的关键措辞是「只能引用工具返回结果里实际出现过的编号与标题」，把标注来源从「写个来源」收紧为「来源必须在证据集内」。规则 2 明确指示换词再查，即所选策略。规则 3 给出弃答的可操作定义（用分数）。

这里不是靠 prompt 解决问题，prompt 只是接口契约；强制力来自工具返回值中带有的出处与分数。若工具不返回这些，prompt 再怎么写都是空的，那就退化为提示词工程，超出题目边界。

## 五、验证

### 5.1 弃答阈值来自标定

规则 3 中的 0.5 并非随手写定。测出 in-scope 与 out-of-scope 问题的 top1 分数：

```
in-scope   印尼进口限制   0.872
           综合市场风险   0.602
           菲印支付物流   0.679
out-of-scope  滤网多久换    0.466
              公司多少员工  0.477
              今天天气      0.316
```

0.5 干净地将两组分开。弃答不是凭感觉，而是依据一个可标定的阈值。

### 5.2 工具调用 trace

给 `TOOL_FUNCS` 加记录器后运行「综合风险」一题：

```
search(query='进入印尼市场的主要风险')
search(query='印尼市场投资风险 挑战')
search(query='印尼物流基础设施 配送难题')
search(query='印尼本地化运营 语言 消费者习惯差异')
search(query='印尼外汇管制 汇率 税务合规要求')
search(query='跨境电商进入印尼的失败原因 壁垒')
read(doc_id='04_regulation')
read(doc_id='05_competition')
read(doc_id='03_logistics')
read(doc_id='02_payment')
```

两点确认了设计意图：模型确实在换词（「投资风险」「物流基础设施」「本地化运营」「外汇管制/汇率」），而非把原句重发六遍，这是模型自主补召回策略成立的前提；它用 `read` 沿 doc_id 把四篇读全，多跳检索被使用。最终答案覆盖政策、竞争、物流、支付四类风险，每条带 `【文档编号｜标题】` 出处。

### 5.3 外域问题不硬凑

对「滤网需要多久更换一次」这一本语料不存在的问题：

```
答：我换了三个角度检索（滤网更换周期、滤网维护、耗材配件），
    结果全部是东南亚跨境电商相关话题，相关度均低于 0.5。
    资料中没有相关信息。 ... 不应凭常识推测。
```

模型换了角度、确认三次均低分后才弃答，并说明最高仅 0.46。这是有依据的弃答，而非直接放弃。

## 六、通用原则

1. 工具被调用了不等于信息拿到了。第三题（调了记忆却没读到）与本题（调了检索却只召回一部分）结构相同。判断时应看工具返回了什么，而非模型是否使用了工具。
2. 加上循环不等于补上召回。ReAct 是允许重复查的框架；召回质量由每次检索的匹配方式与反馈的分数决定。
3. 选择让模型换词，必须同时提供语义匹配与可见分数。换词本质是猜关键词，只有 embedding 能让猜词命中语义相近的正文，只有返回 score 能让模型判断是否继续换词。
4. 出处必须来自工具返回值，不能来自模型记忆。否则是用假出处替换无出处。
5. 弃答靠可标定的阈值，不靠 prompt 中的「不要硬凑」。先测 in-scope 与 out-of-scope 的分数分布，再定线。
6. 改造的重心常常不在题面指向的地方。题面说要多轮检索，但多轮能否奏效取决于底层 `search` 的质量——先修基础，再加循环。

## 七、局限

- `TOP_K` 写死，无重排。当前向量粗排出 top-4 直接给模型；语料变大时应加一层重排，粗排多取、精排少给。
- 阈值 0.5 是在本语料上标定的，换语料或换 encoder 都需重标，写死一个数是权宜而非规律。
- 弃答的决定权留在模型手中：工具只返回 `score`，由模型读分数判断是否弃答。另一条路是把弃答做成硬规则——在 `tools.py` 定义 `MIN_SCORE`，分数不够直接返回「无相关信息」。两条都合法，区别是弃答的决定权在模型还是在代码；生产中常两条并用（硬规则兜底，模型软判断）。
- 多轮检索的收敛由 `max_step=8` 兜底。生产中应按「连续两轮无新增文档」停止，而非纯看步数。
- 幻觉降低了多少仍无量化。以上均为手挑用例的定性验证；要回答需 golden set 与指标。本题恰好提供一组现成的跨文档与外域测试题。

一个 Agentic 循环的价值，等于它每一轮检索的质量乘以它能重复的次数。循环次数容易加，检索质量才是决定能否答全、会不会硬凑的变量。
