# 千人同题，榜有两重

### 塞外纪事之十六

> [!NOTE] 缘起
> 旷野尽头有一片竞试场。入场者不问师承，只领到同一箱数据与一道题。

## 一、题目与数据

竞试场叫 **Kaggle**。主办者把问题写成 **Competition**，把样本装进 **Dataset**：有一部分附着答案，供人训练；另一部分藏起答案，只让人提交预测。

入场者在云端开一册 **Notebook**，用 Python 或 R 清点缺失值、画图、找规律。这一步叫 **EDA**。有人从零写模型，有人先 **Fork** 别人的 Notebook，再换特征、调参数、试不同的结构。

同一份数据，同一道题，能引出成百上千条路。有人追求最朴素的 **baseline**，有人把几个模型 **ensemble** 在一起；有人跑得分，也有人写下详尽的分析，让后来者看懂自己为何这样做。

## 二、公开榜与暗榜

每次提交，场上都会按 **metric** 算分，公开榜随之更新。看着名次上升，人很容易继续追那一小数点；若反复照着公开榜调参数，模型便可能记住公开榜的偶然，离真正的答案反而更远——这叫 **overfitting**。

更要紧的是，许多比赛另有一张不公开的 **Private Leaderboard**。比赛结束后，最终名次由那张暗榜揭晓。公开榜只是途中风向，不是终局判词。

若在验证集里偷看了不该知道的答案，便犯了 **data leakage**。分数一时极好，像从裁判手里偷看了底牌；到了真正未知的数据前，术法就不灵了。

## 三、奖章与讲义

赛后，场中留下提交、讨论与获奖方案。有人赢得奖牌，有人只拿走一套更好的分析方法。冠军的代码也许很巧，却仍要看能否复现、能否解释、能否在另一份数据上站住。

> 分数能排出名次，不能独自证明一个模型理解了世界。

## 笺注

- 「竞试场」者，Kaggle；Competition、Dataset、Notebook 构成主要的解题场景。
- EDA 是探索性数据分析；baseline 是基线模型；Fork 是复制并改进他人的公开 Notebook。
- Public 与 Private Leaderboard 分别提供途中反馈和最终排名；反复追公开分容易过拟合。
- Data leakage 会让验证成绩虚高；Ensemble 则把多个模型的预测合在一起。
