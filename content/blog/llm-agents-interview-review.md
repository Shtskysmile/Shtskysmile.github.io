## 基础

**1. [面/笔] 什么是大语言模型？它和传统预训练语言模型有什么区别？**

大语言模型通常指参数规模更大、训练数据更多、泛化能力更强的语言模型。与传统预训练语言模型相比，它在 zero-shot、few-shot 和多任务迁移上表现更突出。

**2. [面/笔] 大语言模型的训练大致分哪些阶段？**

常见流程是预训练、监督微调，再到对齐阶段如 RLHF 或 DPO。不同模型实现细节不同，但大致都经历「学语言 → 学指令 → 学偏好」。

**3. [面/笔] 什么是位置编码？为什么 Transformer 需要它？**

位置编码给 token 注入顺序信息。因为 Self-Attention 本身对顺序不敏感，如果没有位置编码，模型就无法区分「我爱你」和「你爱我」。

**4. [面/笔] 什么是 tokenizer？为什么大模型通常不用「按完整单词切分」？**

Tokenizer 负责把原始文本切成模型处理的 token。大模型通常用 BPE、WordPiece 等子词切分，而不是严格按完整单词切分，因为这样既能控制词表规模，又能更好处理未登录词、拼写变化和多语言场景。

**5. [面/笔] 什么是 Zero-shot、Few-shot、In-context Learning？**

Zero-shot 是不给示例直接做任务；Few-shot 是在 prompt 中给少量示例；In-context Learning 是模型在当前上下文里通过示例临时适应任务，而不更新参数。

**6. [面/笔] `temperature`、`top-k`、`top-p` 分别控制什么？**

`temperature` 控制采样分布的平滑程度，越低越保守；`top-k` 只在概率最高的前 `k` 个 token 中采样；`top-p` 则在累计概率达到阈值 `p` 的最小候选集合中采样。

**7. [面] 什么是上下文窗口？为什么上下文长度不是越长越好？**

上下文窗口是模型一次能看到的 token 上限。更长的上下文虽然能装更多信息，但会增加计算和显存开销，也可能引入噪声，让模型更难聚焦真正重要的信息。

**8. [面] 什么是 KV Cache？它为什么能显著加速自回归推理？**

KV Cache 把历史 token 的 Key 和 Value 缓存下来，生成新 token 时只需算新位置的注意力，不用重算前面所有 token，因此推理速度显著提升。

**9. [面] 为什么 decoder-only 架构在大语言模型里很常见？**

因为 decoder-only 的自回归训练目标统一、参数利用率高、扩展到超大规模时工程上更直接，而且它在 in-context learning 和生成任务上表现很强，所以逐渐成为主流路线。

## 进阶

**1. [面] SFT、RLHF、DPO 分别是什么？它们的差别在哪里？**

SFT 用高质量指令数据直接监督训练模型；RLHF 通过人类偏好训练奖励模型，再用强化学习优化；DPO 则直接用偏好对比优化，不需要显式训练奖励模型，流程更简化。

**2. [面] prefill 和 decode 分别是什么？它们的性能瓶颈有何不同？**

Prefill 是把整段输入一次性编码进模型，主要瓶颈常在大矩阵乘法和吞吐；decode 是逐 token 生成输出，虽然单步计算量较小，但需要反复串行执行，常更受时延和 KV Cache 访问影响。

**3. [面] 绝对位置编码、相对位置编码、RoPE 分别是什么？为什么很多 LLM 偏好 RoPE？**

绝对位置编码直接给每个位置一个固定表示；相对位置编码更强调位置之间的相对距离；RoPE 则通过旋转方式把位置信息融合进表示，既保留相对位置信息，又比较适合长上下文扩展，所以在很多 LLM 中更常见。

**4. [面] 什么是 RAG？标准 RAG 管道包含哪些环节？**

RAG 是检索增强生成，先从外部知识库检索相关内容，再把结果和问题一起交给模型生成答案。标准流程通常是切分文档、建立索引、检索召回、重排、拼接上下文、生成答案。

**5. [面] 如何评估一个 RAG 系统？检索质量和生成质量分别看什么？**

检索质量常看召回率、命中率、重排后相关性等，核心是「对的文档有没有找回来」；生成质量则看答案正确性、忠实性、引用一致性和用户任务完成效果。也就是说，RAG 评估不能只看最终回答，还要分拆检索和生成两个环节。

**6. [面] 全量微调和参数高效微调分别适合什么场景？**

全量微调适合资源充足且任务差异较大的场景；参数高效微调如 LoRA 更适合大模型快速适配、节省显存，并方便维护多个任务版本。

**7. [面] 什么是 MoE（Mixture of Experts）？它为什么能扩大模型容量？代价是什么？**

MoE 用门控机制让不同 token 只激活部分专家网络，从而在不让每一步计算成本线性爆炸的情况下增加总参数量。它的代价是训练和推理系统更复杂，还会带来路由不均衡、通信开销和稳定性问题。

**8. [面] 为什么长上下文不等于模型真正「用好」长上下文？**

因为能装下更多 token 不代表模型一定能有效定位和利用关键信息。长上下文里常见问题包括注意力分散、关键信息被淹没、「lost in the middle」现象，以及检索到的信息虽然在上下文里但没有被真正利用。

**9. [面] 为什么代码大模型往往需要仓库级上下文，而不仅仅是一段函数？**

因为真实代码行为依赖接口定义、调用关系、配置文件、测试、依赖版本和项目约定。只看单个函数往往无法判断它该调用什么、返回什么、风格是否一致。

**10. [面] Function Calling / 结构化输出为什么重要？**

因为很多真实系统不只是要模型说一段自然语言，而是要它稳定地产生可执行、可解析、可校验的动作或结果。结构化输出能降低解析歧义，也方便和检索、数据库、工具调用、工作流编排等系统模块衔接。

**11. [面] Tool Use 和 Agent 的区别是什么？**

Tool Use 是模型会调用外部工具完成某一步；Agent 则通常还包含任务拆解、状态维护、多轮决策和反馈迭代。可以理解为工具调用是智能体能力的一部分。

**12. [面] 智能体里的 planning、memory、reflection、tool execution 各自扮演什么角色？**

planning 负责分解任务和决定下一步；memory 负责保存历史状态和关键信息；reflection 负责根据结果反思并修正策略；tool execution 负责真正调用编译器、检索器、测试器等外部能力。

**13. [面] 如何评估代码生成模型：`pass@k`、编译通过率、单测通过率、人工偏好、缺陷率分别说明什么？**

`pass@k` 反映多次采样里至少有一个正确答案的概率；编译通过率衡量基本语法和依赖正确性；单测通过率更接近功能正确性；人工偏好反映可读性和实用性；缺陷率则关注是否引入潜在 bug。

## 拔高

**1. [面] 为什么只看 `pass@1` 会误导代码智能体评估？**

因为 `pass@1` 只看第一次答案是否碰巧写对，无法反映系统是否会利用反馈持续修正，也忽略了编译、测试成本和修改范围等工程因素。对智能体来说，过程能力和可验证性同样重要。

**2. [面] benchmark contamination 是什么？为什么在 LLM/代码模型评测里要特别警惕？**

它指评测数据或与其高度相近的内容在训练语料中已经出现，导致模型看起来「泛化很强」，实际上可能只是记住了答案。代码和软件工程评测里尤其要警惕，因为公开仓库、题解、测试样例和 benchmark 描述都很容易被预训练数据吸收。

**3. [面] 为什么 RAG 和 Agent 往往不是二选一，而是经常组合使用？**

因为 RAG 解决的是「知识从哪里来」，Agent 解决的是「任务如何分步做、工具如何调用」。真实系统里，模型往往既需要先检索外部知识，又需要据此做多步决策和执行，所以两者经常组合。

**4. [面] 为什么只把更多仓库文件塞进上下文，并不一定等于更强的软件工程理解能力？**

因为真正的问题不只是「有没有看到」，而是「有没有定位到关键上下文并据此推理」。如果没有检索、重排、结构化组织和工具验证，简单堆更多文件只会增加噪声和计算成本，未必提升决策质量。

**5. [面] 软件工程智能体为什么必须接入测试、构建、静态分析、代码搜索、版本控制工具？**

因为软件工程任务不是单纯生成文本，而是要和真实代码库交互。没有这些工具，智能体既看不清当前工程状态，也无法验证修改是否真的正确。
