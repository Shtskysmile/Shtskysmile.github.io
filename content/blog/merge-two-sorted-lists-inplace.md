# 合并两个有序表：从 O(m·n) 到 O(N) 的原地算法

两个有序线性表 A、B 用向量存放，长度分别为 m、n，B 紧接在 A 之后，占据 `C[1..m+n]`。要求原地把两表合并成一个有序表，即附加空间为 O(1)。

题目本身是数据结构教材的经典习题，但沿着「省空间」这条约束往下追问，会依次遇到三个层次的解法。每一层都对应一种不同的代价取舍，最后得到的结论是：理论最优解在工程上是不可用的，而真正被标准库采用的方案处在中间一层。

全文用 C 风格的数组与下标书写，避免 C++ 模板带来的阅读负担。

---

## 层次 0：逐元素插入，O(m·n) 时间

最直接的原地方案是把 B 看成待插入序列，维护一个已归并前缀 `C[0..len-1]`，初始就是 A。每次取出 B 中当前最小的元素，向前扫描找到插入位置，再把前缀的后半段整体右移一格。

关键在于右移不会破坏尚未处理的 B 元素。右移最多写到 `len`，而 `C[len]` 恰好就是刚刚取出并保存在 `t` 里的那个 B 元素，所以整个过程中只会覆盖刚刚取出的元素本身。

```c
void mergeNaive(int C[], int m, int n) {
    int len = m;                       /* 已归并前缀长度 */
    for (int k = 0; k < n; k++) {
        int t = C[len];                /* B 中当前最小元素，先存起来 */
        int p = len - 1;
        while (p >= 0 && C[p] > t) p--;
        for (int q = len - 1; q > p; q--) C[q + 1] = C[q];
        C[p + 1] = t;
        len++;
    }
}
```

复杂度。空间 O(1)，只多一个 `t` 和几个下标。时间上，被右移的元素必然是大于 `t` 的元素；由于 B 按升序处理，已插入的 B 元素都小于等于 `t`，所以被移动的元素只可能来自 A，每次不超过 m 个。最坏情况（B 全部小于 A）总移动 m·n 次，最好情况（B 全部不小于 A 的最大值）零移动。

| 情况 | 时间 | 空间 |
|---|---|---|
| 最好 | Θ(m+n) | O(1) |
| 最坏 | Θ(m·n) | O(1) |
| 一般 | O(m·n) | O(1) |

这就是教材期望的答案：附加空间达到理论最小，代价是时间可能退化为平方级。

## 层次 1：旋转分治，O(N log N) 时间

层次 0 的瓶颈在于搬运距离。插入一个元素要挪动最多 m 个元素，代价随距离线性增长。要突破这一点，必须让搬运成批发生。

旋转分治的思路是分治。取较长一段的中点作为分界元素，在另一段中二分定位，然后把这个位置之后的部分整体旋转到分界元素前面：

```
A1  A2  B1  B2   ->   A1  B1  A2  B2
```

旋转之后，`A1 B1` 中的每个元素都小于等于分界元素，小于等于 `A2 B2` 中的每个元素，两个子问题因此完全独立，而每个子问题各自仍然有序，于是可以递归。

旋转原语用三次反转实现，代价与区间长度成正比，额外空间为常数：

```c
void reverseRange(int C[], int lo, int hi) {   /* 反转 [lo, hi) */
    --hi;
    while (lo < hi) {
        int t = C[lo]; C[lo] = C[hi]; C[hi] = t;
        lo++; hi--;
    }
}

void rotateRange(int C[], int a, int b, int c) {  /* 交换相邻的 [a,b) 与 [b,c) */
    reverseRange(C, a, b);
    reverseRange(C, b, c);
    reverseRange(C, a, c);
}
```

归并主体：

```c
void mergeRotate(int C[], int lo, int mid, int hi) {
    if (lo >= mid || mid >= hi) return;
    int len1 = mid - lo, len2 = hi - mid;

    /* 递归基：短的一侧只剩一个元素，直接二分定位后整块转过去 */
    if (len1 == 1) {
        int pos = int(std::lower_bound(C + mid, C + hi, C[lo]) - C);
        rotateRange(C, lo, lo + 1, pos);
        return;
    }
    if (len2 == 1) {
        int pos = int(std::upper_bound(C + lo, C + mid, C[mid]) - C);
        rotateRange(C, pos, mid, hi);
        return;
    }

    /* 取较长一段的中点作分界元素，在另一段二分定位 */
    int i, j;
    if (len1 > len2) {
        i = lo + len1 / 2;                              /* 分界元素来自 A */
        j = int(std::lower_bound(C + mid, C + hi, C[i]) - C);
    } else {
        j = mid + len2 / 2;                             /* 分界元素来自 B */
        i = int(std::upper_bound(C + lo, C + mid, C[j]) - C);
    }

    rotateRange(C, i, mid, j);                          /* A1 A2 B1 B2 -> A1 B1 A2 B2 */
    int nm = i + (j - mid);
    mergeRotate(C, lo, i, nm);                          /* 归并 A1 与 B1 */
    mergeRotate(C, nm, j, hi);                          /* 归并 A2 与 B2 */
}
```

调用方式为 `mergeRotate(C, 0, m, m + n)`。这正是 `std::inplace_merge` 在没有可用临时缓冲区时走的路径。

bound 的方向决定稳定性。 分界元素来自 A 时对 B 使用 `lower_bound`，来自 B 时对 A 使用 `upper_bound`。若写反，结果仍然有序，但相等的元素会跨段错位，稳定性丢失。这类缺陷用 `is_sorted` 检查完全发现不了，必须比对元素的原始来源标记。

复杂度。每次递归把较长的一半对半分，最大子问题不超过父问题的 3/4，递归深度 O(log N)。每层所有子问题的规模之和为 N，块交换代价正比于规模，因此总代价 O(N log N)，辅助空间 O(1)（递归栈另计 O(log N)）。

总代价的代价可以换个角度理解：每个元素平均被搬运 Θ(log N) 次。这正是它无法达到线性时间的原因。

| | 时间 | 辅助空间 | 稳定 |
|---|---|---|---|
| 旋转分治归并 | Θ(N log N) | O(1) | 是 |

## 层次 2：内部缓冲区，O(N) 时间

层次 1 已经解决了「搬运距离」问题，但引入了「递归层数」问题：元素在每一层都要参与一次块交换。

缓冲区法的全部目标是把「每个元素被搬 log N 次」降到「常数次」。做法是让交错在块这一级被一次性处理，而不是一层层切下去。

### 核心原语：k 个空位归并两个 k 块

设手上有 k 格缓冲区 `BUF`，以及两个相邻的、各自有序的 k 块 X、Y。目标是原地把它们合并成 2k 个有序元素。

1. 把 X 整块搬入 `BUF`，X 原来的 k 格成为 k 个空位；
2. 从左往右做普通归并，比较 `BUF` 头与 Y 头，每次把较小者写入当前最左的空位；
3. 每写入一个元素，它原来所在的格子成为新空位，空位像传送带一样向右推进。

空位一定够用。 设已写入 w 个元素。风险只在写指针进入 Y 区域时出现，此时会覆盖 Y 中尚未读取的元素。而此时从 X 中读出的元素数为 w − cY；一旦这个数达到 k，说明 X 已全部写完，剩下的全是 Y 的未读元素，而它们本来就在自己的最终位置上。因此空位耗尽的时刻，恰好就是剩余元素已经在正确位置的时刻。k 个空位不多不少。

这个原语用 O(k) 次搬运完成局部归并，而不是 O(k²)。

### 流水线

把数组切成大小 k 的块——每块内部天然有序，因为 A、B 各自有序。维护一个正在归并的 2k 窗口，每一步从 A 侧或 B 侧读入一个新块，与窗口剩余部分归并，输出一个已定型的 k 块，把剩下的一半留作下一轮。块数为 N/k，每步 O(k) 搬运，总计 O(N)。

三种方案的搬运量对照：

| | 每步代价 | 步数 | 总搬运 |
|---|---|---|---|
| 逐元素插入 | O(d) | N | O(N²) |
| 旋转分治 | O(k) | (N/k)·log N | O(N log N) |
| 缓冲区流水线 | O(k) | N/k | O(N) |

差别在于流水线只扫一遍数组，没有递归分层。

### 缓冲区从哪来

前面的讨论都假设「已有 k 个空位」，但数组是满的。解决办法是取出一块元素，就地排序，宣布它临时作废，当作缓冲区。

排序之所以能解决可逆性，是因为作废期间这 k 个元素的原始位置信息会丢失，直接放回必然错乱；但若它们已经有序，其相对次序就是已知的，而一个有序段可以与一个有序段用一次线性归并合并回去。排序把「信息丢失」转化为「延迟决策」——先不决定这 k 个元素去哪，只保证它们之间的次序不丢，最后一次性插回。

### 两处真实的困难

缓冲区自身的归位。 把 k 个排好序的元素插回大小为 N−k 的有序数组，本身是同构的归并问题。若用二分加旋转逐个插入，代价 O(k·N)，前面省下的全部退回。Huang–Langston 的原始方案对最后一步再做一次块处理，把它压到 O(N)，但这一步是整个算法中最不干净的部分，各种伪代码版本常在此处出错。

稳定性。 排序缓冲区那 k 个元素会打乱它们之间的原始次序。若缓冲区中同时含 A、B 中键相等的元素，排序后谁在前无法确定，而稳定性要求 A 的相等元素必须排在 B 之前。解决办法是使用稳定排序并保留来源标记，或在选择缓冲区时避开跨越相等元素的边界。

### 复杂度的分级

| 方案 | 时间 | 辅助空间 | 稳定 | 实现难度 |
|---|---|---|---|---|
| 逐元素插入 | O(m·n) | O(1) | 是 | 10 行 |
| 旋转分治归并 | Θ(N log N) | O(1) | 是 | 30 行 |
| 缓冲区 + 外部 k 格 | Θ(N) | O(k) | 需小心 | 中等 |
| 缓冲区 + 内部 k 格 | Θ(N) | O(1) | 需小心 | 极难 |

第三行值得单独强调：若允许额外申请 k 格（例如 512 个元素），线性时间是可以相对干净地实现的。 工程中的块归并变体走的都是这条路，k 取常数，常数项低，代码数百行而非数千行。

第四行才是理论最优，由 Huang–Langston（1988）、Geffert–Katajainen–Pasanen（2000）等工作给出。它的价值主要是理论性的：证明 O(N) 时间、O(1) 空间、稳定性三者可以同时满足。

> [!NOTE] 理论最优不等于工程最优
>
> 缓冲区法的常数项极大：块内排序、缓冲区反复搬运、边界二分，实际指令数高于旋转归并。`std::inplace_merge` 在有内存时根本不走这条路，而是用 O(N) 额外空间做归一化拷贝，比较次数降到 O(m·log(n/m+1))，比任何原地版本都快。缓冲区法只是理论上的天花板。

## 汇总

| 层次 | 方案 | 时间 | 辅助空间 | 稳定 | 实践建议 |
|---|---|---|---|---|---|
| 0 | 逐元素插入 | O(m·n) | O(1) | 是 | 考试标准答案 |
| 1 | 旋转分治归并 | Θ(N log N) | O(1) | 是 | 无缓冲区时的实用首选 |
| 2 | 内部缓冲区 | Θ(N) | O(1) | 需小心 | 理论最优，工程不用 |

这条链条呈现的是时空权衡逐级逼近理论上限：

- 层次 0 用最小的空间换来最坏平方时间；
- 层次 1 在保持 O(1) 空间的前提下拿到最坏 O(N log N) 保证，代码量可控，是工程上的正确答案；
- 层次 2 触及理论下界，但代价是常数项与实现复杂度，标准库不采用；

若只回答「最小附加空间」这一约束，层次 0 即为完整答案。若要展示对时空权衡的完整理解，应补充说明层次 1 与层次 2 的存在性及其代价。
