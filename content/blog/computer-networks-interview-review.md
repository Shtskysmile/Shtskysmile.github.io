## 基础

**1. [面/笔] OSI 七层模型和 TCP/IP 四层模型分别是什么？**

OSI 七层是物理层、数据链路层、网络层、传输层、会话层、表示层、应用层；TCP/IP 常分为链路层、网络层、传输层、应用层。面试里通常强调 TCP/IP 更贴近真实互联网实现。

**2. [面/笔] TCP 和 UDP 的区别是什么？分别适合哪些场景？**

TCP 面向连接、可靠传输、有序、带流量和拥塞控制，适合网页、文件传输、数据库连接。UDP 无连接、开销小、延迟低，适合直播、语音、游戏、DNS 等对时延敏感场景。

**3. [面/笔] TCP 三次握手和四次挥手的过程是什么？为什么不能两次握手？**

三次握手是 `SYN -> SYN+ACK -> ACK`，目的是确认双方收发能力都正常。两次握手无法保证服务端知道客户端是否收到了确认，也难以避免历史连接请求带来的问题。

**4. [面/笔] HTTP 和 HTTPS 的区别是什么？**

HTTPS = HTTP + TLS/SSL。它在 HTTP 之上增加了加密、身份认证和完整性校验，防止窃听和中间人攻击，代价是握手和加解密开销更高。

**5. [面/笔] HTTP 为什么说是无状态协议？无状态有什么优缺点？**

无状态指服务端默认不记住客户端上一次请求的上下文。优点是实现简单、易扩展、便于负载均衡；缺点是登录态、购物车等信息要额外通过 Cookie、Session、JWT 等机制维护。

**6. [面/笔] Cookie、Session、JWT 分别是什么？各自适合什么场景？**

Cookie 是浏览器保存的一小段数据；Session 通常是服务端保存会话状态，客户端只带 Session ID；JWT 是客户端自包含令牌。Session 控制力强，JWT 更适合分布式和跨服务场景，但吊销和刷新更麻烦。

**7. [面/笔] DNS 的作用是什么？从输入网址到访问页面大致发生了什么？**

DNS 把域名解析成 IP 地址。大致流程是先查本地缓存和 DNS，建立 TCP/TLS 连接，发送 HTTP 请求，服务端返回 HTML 和资源，浏览器再解析渲染页面。

**8. [面/笔] GET 和 POST 的区别是什么？幂等性是什么意思？**

GET 常用于获取资源，理论上不应修改服务器状态；POST 常用于提交数据。幂等性指多次执行和执行一次的效果相同，GET、PUT、DELETE 通常设计成幂等，POST 不一定。

**9. [面/笔] 什么是 IP 地址和子网掩码？**

IP 地址用于标识网络中的主机。子网掩码用于区分网络号和主机号，从而判断哪些主机在同一子网、路由该如何转发。

## 进阶

**1. [面] TCP 的流量控制和拥塞控制分别是什么？有什么区别？**

流量控制是端到端的，防止发送方发太快把接收方缓冲区撑爆，主要靠滑动窗口；拥塞控制是为了防止网络本身过载，典型机制包括慢启动、拥塞避免、快重传和快恢复。

**2. [面] 为什么会有 `TIME_WAIT`？为什么不能直接省掉？**

`TIME_WAIT` 让主动关闭方等待一段时间，确保最后一个 ACK 能到达对方，也让旧连接中的迟到报文在网络中自然消失。省掉后可能造成新旧连接报文混淆。

**3. [面] HTTP/1.1、HTTP/2、HTTP/3 的核心差别是什么？**

HTTP/1.1 主要靠长连接和管线化，但仍有队头阻塞。HTTP/2 引入二进制分帧、多路复用、头部压缩。HTTP/3 运行在 QUIC/UDP 之上，进一步减少握手成本并改善传输层队头阻塞。

**4. [面] 长连接和短连接的区别是什么？**

短连接每次请求都重新建连和断连，简单但握手开销大；长连接复用已有连接，延迟更低，适合频繁交互。现代 Web 和在线服务大多偏长连接。

**5. [面] 什么是 CDN？它通常解决什么问题？**

CDN 是内容分发网络，把静态资源缓存到离用户更近的边缘节点。它主要解决跨地域访问慢、源站压力大和高并发下的稳定性问题。

**6. [面] 反向代理和负载均衡分别是什么？**

反向代理位于服务端前面，对外统一暴露入口并转发请求；负载均衡则在多个后端实例间分配流量，提高吞吐和可用性。很多网关同时承担这两类职责。

**7. [面] WebSocket 和 HTTP 轮询的区别是什么？**

HTTP 轮询需要客户端反复发请求获取新数据，延迟高且浪费带宽。WebSocket 建立一条持久全双工连接，服务端可以主动推送消息，更适合实时交互。

**8. [面] RPC 和 REST 的区别是什么？如果要做模型服务接口你会怎么选？**

REST 更偏资源风格，接口通用、调试方便；RPC 更偏函数调用，协议更紧凑、性能通常更好。若对外开放和生态兼容优先，可选 REST；若内部高频调用、性能敏感，RPC 更合适。

## 拔高

**1. [面] 如果要做在线问答或模型服务，为什么很多系统会选择长连接或流式返回？**

因为大模型响应通常较慢且答案是一段连续生成的内容，流式返回能让用户先看到前几个 token，显著改善主观等待体验。长连接还能减少反复建连的开销，更适合连续对话或实时交互。
